# Roadmap: gates, not promises

## 0. One real machine and one care loop — NOW

Create a machine record; add a genuine photo, note, history item or diagnostic export; produce an evidence-linked brief; record the actual outcome of one check. Manual or agent-assisted execution is enough. Success: Colm can understand and use the brief and a relevant person can act on it.

## 1. Earn another user

Show the real brief to a T4 owner or specialist. Ask for a real case, compare its usefulness to their current process, and make a paid-pilot ask. Record objections and what they would pay for. Gate: a real commitment or paid pilot before substantial product building; if none, park commercial development and keep it personal.

## 2. Capture and compare

Build a small local-first tool that stores dated observations, photos and outcomes, with human review. Compare repeatable observations only when context is available. No claims of prediction without validation.

## 3. Add the first sensor when a real problem justifies it

Choose camera, sound, thermal, voltage, pressure or ECU access for a specific failure mode. Define placement, baseline conditions, failure to detect, false alarm rate, safe installation, and independent verification before making claims. Test on the actual machine. Avoid promises about unsupported ECUs.

## 4. Closed-loop assistance

Maintenance schedule, owner-approved contact with a mechanic, parts identification and repair outcomes. Each capability is gated by user needs and evidence. Consider agents or physical robotics only when they improve a demonstrated task.

## Future

Other machine profiles; privacy-preserving knowledge shared across owners; mobile inspection robots. These are hypotheses, not commitments.
