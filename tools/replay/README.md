# Offline capture replay prototype

This is a narrow Rust counterpart to Caretaker's existing Python observation log.
It replays bytes; it does **not** open a serial port, transmit CAN frames, infer a
repair, or replace the T4/KW1281 adapter. There are no third-party Rust packages.

## What it demonstrates

- a small unsigned little-endian DBC reader and raw CAN CSV replay;
- least-squares scale/offset fitting on a calibration capture;
- fixed-decoder verification on a separate, time-aligned holdout reference;
- absolute RMSE, maximum-error, correlation, sample-count, and range gates;
- an expected wrong bit-field match that remains `UNCONFIRMED` and emits raw
  `can_frame_0x123` observations rather than false `vehicle_speed` values;
- semantic preservation of the existing six-record synthetic T4 demonstration,
  including source, units, context, `details`, and `simulated` flags.

All included CAN data and references are **simulated fixtures**. They are not CSS
Electronics samples or real vehicle evidence. The T4 input is generated by the
existing Python demo and is also synthetic. `CALIBRATION_ONLY` never counts as
independent verification.

## Test and demo

From the repository root:

```sh
cargo test --manifest-path tools/replay/Cargo.toml
sh tools/replay/demo.sh
```

The demo writes to `target/caretaker-replay-demo/` by default. An optional first
argument chooses another output directory. It runs the original T4 Python demo,
the Rust calibration/holdout/wrong-match cases, and an independent Python script
that compares T4 JSON values and recalculates every CAN holdout result.

To replay one capture directly:

```sh
cargo run --manifest-path tools/replay/Cargo.toml -- can \
  --capture tools/replay/fixtures/can-holdout.csv \
  --reference tools/replay/fixtures/can-holdout-reference.csv \
  --dbc tools/replay/fixtures/vehicle-speed.dbc --signal VehicleSpeed \
  --machine demo-can --simulated --output /tmp/can-observations.jsonl
```

`can` exits 2 when verification is `UNCONFIRMED`. That is a valid diagnostic
result, not a licence to force a physical label. CAN timestamps must be UTC and
end in `Z`; reference rows carry value, unit, and source. This prototype supports
classic CAN payloads up to eight bytes and DBC `@1+` signals only. Production work
should use a maintained DBC/CSV library and preserve its validation report.

## Adapter boundary

Another supported machine needs a capture, a candidate decoder, a sourced
reference, and a test; it does not need a new Rust acquisition path. Unsupported
geometry or units are rejected. Real acquisition remains in existing tools such
as SocketCAN, CANboat, or `tools/t4/t4_logger.py`, behind their own permissions
and safety controls.
